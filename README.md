# UTube Music

iPhoneに曲を保存し、同じアプリでお気に入り・プレイリスト・オフライン再生を扱う個人用音楽アプリ。AI機能はありません。YouTube / YouTube Music / Spotifyの公式アプリではありません。

対象: iPhone 14 / 利用者申告 iOS 27.0.1。開発PC: Windows。更新日: 2026-11-03。

## 0.3.10：通信量の削減

歌詞・検索結果・検索候補・アルバムなどの情報をメモリで一時的に再利用します。ジャケットの取得を画面間で共有し、HTTPキャッシュを利用します。オンライン再生の先読み設定を短縮し、同じ音源の冒頭解析結果を再利用します。保存済み音源はローカルを優先し、音声の自動ダウンロードは行いません。

## 0.3.9：年齢確認が必要な動画と公式音源

オンライン再生でYouTubeから年齢確認を求められた場合、YouTube Musicで同じ曲の公式音源を探します。元の曲IDで再生キューやライブラリを管理し、歌詞と再生時間は実際に再生する音源を使います。確実に照合できない場合は年齢確認が必要な旨を表示します。

## 0.3.8：再生画面の同期歌詞カード

再生画面を下にスクロールすると、歌詞カードに現在の行とその周辺の歌詞が表示されます。カードをタップすると全画面で歌詞を表示します。時刻なしの歌詞はテキストで表示します。

## 0.3.7：検索からの再生と歌詞

「検索」の曲の行をタップすると通常再生が始まり、後続の検索結果を再生キューに入れます。ダウンロード済みの音声があれば優先します。未保存の曲はその場でストリーミングし、「…」や再生バーのお気に入りボタンで追加できます。

再生画面の下にある「歌詞」を開くと、同じ音源IDに時刻付き歌詞がある場合は再生に合わせて行を強調します。行をタップしてその位置へ移動できます。時刻のない歌詞はテキストで表示します。別バージョンの歌詞は流用しません。

## 0.3.6：検索入力中の表示領域とタップ範囲

検索欄を編集中／キーボード表示中は、ミニプレイヤー・試聴バナー・下部3タブをレイアウトから一時的に外します。再生そのものは継続します。「完了」・候補選択・キーボードの検索で編集が終わると下部の操作部が戻ります。検索入力中は大きな見出し・補助行・曲／プレイリスト／アルバムの切替を畳み、検索候補の一覧を優先します。候補を縦にスクロールしてもキーボードを閉じず、明示的に完了／検索できます。「曲を追加」画面も入力中は見出しをコンパクトにします。iOSキーボード自体の変換候補の高さを変更する機能ではありません。

アプリの検索候補は横幅いっぱい・高さ56ポイント以上とし、文字だけでなく左右の余白もタップできるようにしました。長い候補は2行まで表示します。検索・完了・全選択・選択解除・保存状況の再試行／キャンセルなどの文字操作は、ボタンのラベル内に44ポイント以上の操作領域を持たせました。下部タブ、お気に入り／プレイリスト行、試聴、追加／さらに表示の操作範囲も確認・調整しています。検索の種類や保存・再生の機能は維持します。

## 0.3.5：オンライン曲が終端直前で止まる問題への対応

利用者画像では「スターライトパレード」がオンライン再生の6:31／6:32で止まり、4GとWi-Fiの両方で再生中の表示が残る状態。該当するYouTubeリンクは不明のため、同じ実音源を直接解析したとはしていません。

従来は動画／検索の曲情報を `forwardPlaybackEndTime` に設定し、音声側の長さが判明しても、登録の長さが0でない限り表示を更新しませんでした。自然終了通知だけで曲送りを行い、通知漏れやデータ待ちで終端に到達しない場合の復旧がありませんでした。

オンラインの終了位置は検索の整数秒で強制指定しません。再生アイテムの音声時間を監視し、既存の公開メタデータ取得から同じAAC形式の `approxDurationMs` も受け取ります。通常の1秒未満の差では音声側の時間を優先し、明らかに過大なコンテナ時間だけを独立したAAC時間で補正します。動画情報は長さが不明な間の表示のみに使用します。保存ファイルやライブラリ登録は変更しません。

再生時間のコールバックが止まっても動く監視を追加。再生を要求していて、確認できた実終端のごく近くで2秒以上進まないときは終了処理を補助します。単に「最後の1〜2秒だから」という条件では曲送りしません。終端より手前の通信停止は12秒を目安に一度だけ音声URLを取り直し、同じ位置から再開します。再度進まなければ停止して案内し、無限に再接続しません。ユーザーの一時停止・シーク・曲変更で監視状態をリセットし、遅れて届いた終了通知で曲送りしないようにしました。通信待ちは画面にも表示します。

## 0.3.4：冒頭の無音を初期状態で自動スキップ

設定「冒頭の無音を自動スキップ」は初期状態でオン。先頭8秒以内でほぼ無音が続き、その後に音が始まる曲は、音の始まりの約0.15秒前から本再生を開始します。−70dBFS付近の厳しいしきい値・30msの継続を使い、0.5秒未満のごく短い空白は飛ばしません。曲の途中の間奏・無音は対象外です。音の始まりを確認できない場合は推測せず元の先頭から再生します。環境音・ノイズがあるMVのイントロや、8秒を超える無音の除去は保証しません。

保存曲は音声を読み取るだけで確認し、元の音源を書き換えません。オンライン曲は追加のRangeリクエストで先頭の最大256KBだけを一時的に確認します。206 Partial Contentと範囲を検証し、サーバーが全体を返す200応答は受け取り続けず中止します。先頭だけでは解析できない形式や通信失敗では0秒から再生します。一時ファイルは成功・失敗・キャンセル時に削除し、オフライン用の保存曲として登録しません。強制終了時に残った確認用ファイルも、専用一時フォルダー内のものだけを次回起動時に掃除します。先頭だけのM4AをiOSが直接開けない場合は、取得済みの完全なAAC-LCパケットだけを再圧縮せず一時的なADTS形式に包んで確認します。検出結果だけを曲の情報に記憶して次回・リピートに再利用します。初回確認の待ち時間と通信が発生する場合があります。

曲の「…」→「冒頭の無音をスキップ」で「秒数を指定」を選べば、曲ごとに0.25秒単位・最大30秒の開始位置を指定できます。「現在の再生位置を使う」も用意。0秒を指定すれば、その曲は自動スキップしません。「自動（初期設定）」に戻せます。全体設定のオン／オフは次回の曲開始から反映し、手動指定は全体の自動設定と別に保持します。

通常の再生・曲送り・シャッフル・リピートで同じ開始位置を使用します。手動シークで0秒へ戻って聴くこともできます。音源・ジャケット・お気に入り・全プレイリストと曲順は維持します。元の音源の再生位置を表示し、表示上の曲の長さは切り詰めません。15秒の試し聞きとは独立した本再生の設定です。

## 0.3.3：配布ファイルの整理と再生音量の調整

配布アプリからCPython標準ライブラリの開発用回帰テスト `python/lib/python3.13/test` を除外しました。`unittest` を含む実行ライブラリ、ネイティブ拡張、依存パッケージのメタデータ、証明書、ライセンスは維持します。未参照の `Song.sourceURL` とRootViewの不要なimportを削除。以前のIPA・デザイン案・ビルド用スクリプトはアプリ本体に同梱していません。既存の再生・保存・検索・プレイリスト機能は維持します。

設定「曲ごとの音量差を抑える」は初期状態でオン。保存曲は初回再生前に音声を読み取り、モノラル／ステレオのK重み付け・400ms窓・100ms間隔・絶対／相対ゲートで曲全体の音量を測定します。−14 LUFSより大きい曲だけを再生時に減衰し、小さい曲は増幅しません。結果を音声ファイル名とともに索引へ保存し、次回は再測定しません。音声ファイル・ジャケットを再圧縮せず、iPhoneのシステム音量も変更しません。初回測定中はミニプレイヤーに「音量を確認中…」と表示します。測定失敗・対象外の形式・短い音声・無音は元の音量で再生します。

オンライン再生・試し聞きはYouTube Musicの公開音量情報を取得できた場合に、その基準を超えた分だけ下げます。取得できない場合は元の音量です。音声を丸ごとダウンロードしてオンライン曲を測定する方式は使いません。保存曲も含め、すべての曲を厳密に同一音量へそろえる機能ではありません。Spotifyの小さい曲の増幅やアルバム単位の処理まで再現するものではありません。[Spotifyの音量基準](https://support.spotify.com/us/artists/article/loudness-normalization/)、[ITU-R BS.1770](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I/en)。

## 0.2.3の状態：試し聞き

検索結果・曲を追加・アルバム／プレイリスト詳細の再生アイコンから、保存前に最大15秒の試し聞きができます。取得元のチャプター名にサビ／Chorus／Refrainがある場合はその位置、ない場合は曲の途中から再生します。サビの自動解析は行いません。短い曲は曲末までです。試し聞き終了・停止時は、直前に再生中だった曲を元の位置から再開します。

保存済みの曲はローカル音声を使い、未保存曲は通信して再生します。試し聞きでライブラリへ音声ファイルを保存しません。AVPlayerの先読みがあるため、通信量が厳密に15秒分に収まる保証はありません。

ジャケット画像の選択・保存サイズ・JPEG品質・表示デザインは従来通りです。追加の縮小・再圧縮・削除は行いません。音声も従来と同じAACを選び、ビットレート低下や再圧縮は行いません。既に圧縮済みの音声なので、品質を変えずに大幅な容量削減ができるとはしていません。同じ保存曲を複数プレイリストから参照する既存の仕組みも維持します。0.2.2の再生時間修正を含みます。

**0.2.3の更新用IPAを生成しました。** [成功したビルド](https://github.com/iwamoto0414yuuki-droid/UTubeMusic/actions/runs/39218917599)。ネイティブ45件・Python19件の合計64件が成功。試聴の自動終了と元の再生への復帰、停止後の遅延応答の無効化、保存済み曲のオフライン試聴、不正な再生範囲と取得先の拒否を検証し、試聴ボタン・停止ボタン・バナーのネイティブ画像を確認しました。検証済みソースは `7822edaa3d0bd14779894648d7f03195b2ff3521`。実際のiPhoneとYouTube音声の実通信再生は未検証です。

## 0.2.2：再生時間・後半無音の修正

利用者から、0.1系では正常だったが0.2系では保存した全曲が約2倍の長さになり、後半が無音になるとの報告。0.1.0と0.2.1の差分では音声転送・保存時の長さ判定・PlayerStore本体に変更はなく、バージョン更新との直接の因果関係は未確定です。問題の実ファイルは未取得です。

追加の利用者情報では「保存した音声ファイルは正常で、アプリの再生時だけ長さが倍になる可能性」が示されました。従来はAVAssetのdurationを保存し、プレイヤーが索引内の値をそのまま表示・シーク範囲に採用していました。0.2.2はAVAudioFileの音声フレーム数から長さを独立に確認し、再生画面・ロック画面・シーク範囲・AVPlayerItemの再生終端を揃えます。旧索引の長さが誤っていても、再生時に再確認します。

再現検証：合成した約3秒のAACを含むDASH M4Aで、iOSのAVURLAsset.durationが5.975328798185941秒を返しました。同じファイルをWindowsのFFmpegで実デコードした音声は3.0418秒でした。これは実際の利用者ファイルの解析ではありませんが、「音声データは正常でも、Apple側の時間解釈とアプリの登録値が約2倍になる」経路をネイティブテストで再現しています。

既存の音声ファイルは書き換えず、索引の時間情報と再生側の終端だけを修正します。配信用M4AでAVAssetの長さが誤っていても、独立に測った実音声の長さを使います。音声の再圧縮・無音判定によるカット・再生時間の単純な半分への変更は行いません。

既存曲はホームの設定 →「保存した曲の再生時間を修復」から端末内でまとめて修復できます。お気に入り・プレイリスト・曲順・追加日時・音声ファイルを維持します。索引保存の失敗時も元の曲を保持します。手動で読み込んだ音声ファイルは一括修復の対象外ですが、再生時の長さ確認は適用されます。

**0.2.2の更新用IPAを生成しました。** [成功したビルド](https://github.com/iwamoto0414yuuki-droid/UTubeMusic/actions/runs/39216359426)。ネイティブ39件・Python16件の合計55件が成功。約2倍のコンテナ時間の再現、音声フレーム数による実長の取得、DASHの実終端での曲送り・1曲リピート、誤った旧索引の修復、音声ファイルの完全一致、メンバーシップ・追加日時の保持、索引書込失敗時の保護を検証しました。検証済みソースは `ae1d941abe7958b1a540b401a672bf9f879e9fdc`、修正ブランチは `fix/audio-duration-022`。実際の利用者ファイルの解析と更新後の実機確認は未実施です。

## 無料でビルドする経路

GitHub公式は、公開リポジトリで標準GitHub-hosted runnerを使うActions実行を無料と案内しています。**有料のlarger runnerは使いません。** 今回のワークフローは公開リポジトリの場合のみmacOSジョブを実行します。非公開リポジトリでは実行をスキップし、無料枠から有料利用へ流れる構成にしません。

手動実行のみ、同時1件、最大30分。成果物の保持は1日、キャッシュは使いません。Actions / Packagesの保存枠も共有されるため、他のリポジトリを含めたアカウント全体の保存量と請求設定を実行前に確認します。今回の設定だけでアカウント全体の課金設定を変更することはできません。無料を条件として、枠超過で課金する設定にはしません。

1. このフォルダーだけを新しいリポジトリのルートに置く。既存LocalTubeや親フォルダー全体をアップロードしない。
2. ソースの公開について利用者の同意を得る。2026-10-18に本人の承認を得て、[UTubeMusic](https://github.com/iwamoto0414yuuki-droid/UTubeMusic) にソースのみを公開しました。曲・認証情報・既存LocalTubeのデータは含めません。
3. Actions → `Build personal iPhone app (free standard runner)` → Run workflow。
4. シミュレーターのビルド・ネイティブテストを通してから実機用ビルドを行う。
5. 成功時の `UTubeMusic-0.3.10-SideStore` からIPAとSHA256を取得する。失敗はログを調べて修正し、成功するまで導入用として配布しない。0.3.10のソースは `perf/reduce-data-0310` ブランチです。

出力: `build/UTubeMusic-0.3.10-unsigned.ipa`。Windowsへ取得した配布用コピーは `release/` に保存します。これは自分のApple AccountでSideStoreが署名する前のIPAです。署名証明書・パスワード・ペアリングファイルをCIへ送る必要はありません。成果物のActions保管期限は1日なので、取得したIPAを手元に保管してください。

Macがある場合はXcodeとXcodeGenを用意して `bash scripts/build_ipa.sh` で同じビルドを実行できます。Windowsでは実行できません。

## SideStoreで入れる

**SideStore・LocalDevVPN・無料Apple Accountによる通常の7日更新は無料**です。一般の有料VPN契約は不要です。初期設定ではWindowsとUSBケーブルを使います。

1. 公式手順に従いLocalDevVPNをApp Storeから導入。
2. WindowsのiloaderとAppleの接続ソフトを用意し、USB接続、PCの信頼を行う。
3. 本人がApple Accountへログインし、SideStore Stableを導入。
4. iPhoneで開発者の信頼・Developer Modeを設定。これらの認証・端末設定は本人が行う。
5. Wi-Fi + LocalDevVPN接続中にSideStoreを開き、最初にSideStore自身を更新。
6. 成功したIPAをiPhoneの「ファイル」に置き、SideStoreのMy Appsの追加操作から選ぶ。
7. 起動・曲の保存・機内モード再生・ロック中の連続再生を確認。

通常の更新: Wi-Fi → LocalDevVPNオン → SideStore → My Apps → UTube MusicとSideStoreの期限を更新。通常7日が切れる前に行います。自動更新は毎回成功すると仮定しません。期限切れ時はアプリを削除せず再署名を検討し、ライブラリを保護します。SideStore自身の期限切れやペアリングの失効時にはWindowsからの復旧が必要になる場合があります。
